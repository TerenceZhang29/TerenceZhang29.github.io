# Perform a final design QA pass on the OS portfolio

Review the entire website as a senior product designer and frontend engineer.

Do not add major new features.

Instead, identify and fix anything that makes the website feel:

- generic
- cluttered
- gimmicky
- visually inconsistent
- difficult to navigate
- insufficiently polished
- unlike a real operating-system-inspired interface

## Design benchmark

The target feeling is:

**Linear / Vercel-level polish + modern desktop OS + software-engineering personality.**

It should feel custom-designed.

Not like a template.

Not like a terminal theme.

Not like a cyberpunk website.

## Check these specifically

### Typography

Ensure:

- headings use Geist
- body uses Inter
- technical elements use Geist Mono
- hierarchy is obvious
- line lengths are comfortable
- headings don't dominate excessively

### Color

Ensure:

- background is predominantly `#080B0F`
- surfaces use `#11161A` / `#151A1F`
- borders use `#232A31`
- primary text is `#E6E6E6`
- green `#A3E635` is the primary accent
- blue/purple remain secondary

The accent colors should feel special because they are used sparingly.

### Spacing

Look for:

- cramped windows
- inconsistent padding
- excessive empty space
- misaligned icons
- inconsistent section spacing

Normalize spacing using a consistent scale.

### Windows

Every window should feel like part of the same OS.

Check:

- title bars
- controls
- borders
- radius
- shadows
- padding
- typography

They should all share the same visual grammar.

### Navigation

A visitor unfamiliar with the OS concept should still understand how to:

- view projects
- view experience
- learn about me
- find the resume
- contact me

If the metaphor interferes with this, simplify the metaphor.

### Mobile

This is a mandatory pass.

On mobile:

- no horizontal scrolling
- no tiny desktop windows
- no unusable drag interactions
- no overlapping UI
- no desktop-only navigation
- readable text
- accessible buttons
- easy project browsing

Use full-screen application views where appropriate.

### Content

Make sure the redesign did not accidentally:

- remove existing projects
- remove links
- alter dates
- change job titles
- remove resume access
- remove social links
- fabricate content

Preserve the original content.

### Accessibility

Check:

- keyboard focus
- focus visibility
- color contrast
- semantic buttons
- screen-reader labels
- reduced motion

### Performance

Check for unnecessary:

- JavaScript
- dependencies
- animations
- re-renders
- large assets

The website should remain lightweight.

## Final instruction

Do not keep adding visual effects.

If something looks "cool" but makes the portfolio harder to use, remove it.

The strongest version of this design is **restrained**.

The final impression should be:

> "This is a software engineer's personal computer, and I somehow ended up exploring their portfolio."

That is the experience we want.
